# Public session details and occurrence sharing

The first version follows the approved Stitch Session Details composition: a contained court image with a status badge, title and venue beneath it, one compact date/level/price card, an embedded location map with a directions action, joined-player preview, an open description section, past-session reviews, policies, and a bottom action bar. It reuses existing typography, badges, buttons, sheets and toasts.

## Links and access

The organizer occurrence header shares the **specific occurrence** through the native share sheet. View public session opens the same read-only detail in the app. The HTTPS link is `${EXPO_PUBLIC_SITE_URL}/session?id=<UUID>` (local development hosts fall back to `https://palla.vercel.app`); the query route works with Expo static hosting for occurrences created after a build. `palla://session?id=<UUID>` opens it in the installed native app. HTTPS links render the read-only page when the branch is deployed. Universal/App Link association and store fallback are not configured by this feature.

Only public, non-draft occurrences are available anonymously. Private occurrences remain owner-only and do not have a shareable public link; this first version does not introduce invitation tokens or change saved visibility. Missing, malformed, private, inactive-host/venue and removed occurrences share the same unavailable state. Cancelled/completed public links remain readable with registration blocked.

`get_public_session_detail` is a narrowly projected, read-only RPC over existing sessions, venues, series and registrations. Base-table privileges/RLS remain unchanged. Anonymous visitors receive host display information and aggregate confirmed occupancy, but no participant identities. Completed signed-in profiles receive up to twelve confirmed players' first names/last initials, avatars and playing categories. Player IDs, registration IDs, attendance, contacts, queue contents and series draft input are excluded. Query caches are account-scoped and not persisted; the detail refetches every 30 seconds while active. The client also recalculates status from the scheduled times.

The public SECURITY DEFINER endpoint intentionally returns only this projection with a fixed empty search path and explicit anonymous/authenticated EXECUTE grants. Its public execute advisor findings are expected for this anonymous read API, not a grant to underlying tables. See the [Supabase function advisor explanation](https://supabase.com/docs/guides/database/database-linter?lint=0028_anon_security_definer_function_executable). Existing project advisories outside this feature are unchanged.

## First-version boundaries

Joining and saving sessions remain deferred features. No heart/save control is shown. An available session's Join session action explains that registration is coming soon and does not write a registration. Existing confirmed/waitlisted viewers and the host have their actual status shown. Full, not-open, closed, in-progress, completed and cancelled sessions block joining. The browser's Open in Palla action opens the occurrence's custom deep link.

The artwork is the existing bundled generic court image used in review summaries, **not a photograph of the saved venue**. The approved Frosted button map uses actual OpenFreeMap/OpenStreetMap vector streets, styled with pale lilac ground and white roads. Labels, points of interest and embedded navigation controls are omitted. A centered solid white button uses the existing button primitive, a map icon matching the text and the subtle raised shadow. Attribution remains visible and linked. The existing WebView renders the map; no native dependency, database change, location permission or secret key is added.

The saved address is resolved independently through the Photon OSM adapter, through the repository/service/query layers. Queries are account-scoped, memory-only and fresh for 24 hours, without automatic focus refetch or automatic retry. No authentication headers, user IDs, player data or device position are sent to the provider. Ambiguous neighborhood results exclude unrelated POIs; missing or unresolved locations show a fallback rather than fabricated coordinates. Photon is a community geocoding service with no application SLA; its adapter can be replaced if usage requires a dedicated service. OpenFreeMap permits public commercial use without keys. Provider references: [Photon](https://photon.komoot.io/), [OpenFreeMap](https://openfreemap.org/).

Page gestures scroll the session. Loading has a skeleton; failed/timed-out loads offer Retry map while retaining directions. Addressless venues retain directions when a Google place ID exists. The external directions link still uses the saved Google place ID when available. The context map does not assert a checked court entrance or independently verified location. Missing descriptions, empty occupancy and unavailable venue details retain explicit fallbacks.

## Verification

`supabase/tests/public-session-detail.sql` uses rollback-only Auth/product fixtures to verify anonymous public reads, private/draft rejection, aggregate counts, absence of participant identities and contacts, signed-in limited player projection, actual registration status, owner-only private preview, cancelled/completed states and missing IDs. The connected project's migration is applied. The rollback suite passed and left no test occurrences behind.

Native evidence and checks are recorded in `docs/native-testing.md`; screenshots are ignored under `.impeccable/review/native/public-session/`. The no-write native preview is `palla://sessions-preview/public-session`, with `state=full|cancelled|completed|closed|not-open|anonymous|empty|error|loading|map-unavailable|map-missing`. Share previews open the native sheet for a clearly labelled illustrative occurrence; no recipient is selected. UI validation uses native apps, not browser screenshots.

The Before you join section groups registration opening/closing times, player cancellation cutoff, optional arrival instructions and payment instructions into labelled icon rows. Missing deadlines retain the existing fallback copy, and all displayed times use the session timezone.

## Past-session reviews

The approved rating overview and white review cards appear before Before you join. The summary includes the average, review count, and all five rating buckets. Two recent cards show the reviewer’s public name/photo, occurrence date, rating, and optional comment. See all opens a dedicated, paginated native page. Empty reviews show No reviews yet without a fabricated rating; loading and error/retry use shared primitives. Larger text stacks the overview and card headings. No tags, host redesign, or new review-writing rules are introduced.

`get_public_session_reviews` resolves the occurrence’s series internally and reads published reviews of ended, public, published/completed occurrences from that series and organizer. Each review counts equally, including repeat players at different occurrences. Private, cancelled, future, hidden, and removed sources are excluded. Summary values span the entire eligible set; pages use descending `(created_at, id)` cursors, bounded to 20 items. Public identity is an explicitly approved review field; registration/player IDs, contacts, attendance and series draft data remain excluded. Target visibility follows the existing public-detail API. The additive migration is applied to the connected Palla project; no base grants or tables changed. Its anonymous SECURITY DEFINER advisor is intentional for the narrow public projection, with an empty search path and explicit grants; see the advisor link above.

The client follows repository/service/query boundaries, uses account-scoped memory-only queries, and invalidates public feedback when a review is saved/removed. Detail refresh also refreshes its two-card preview; the full list supports pull-to-refresh and explicit Load more. Development-only preview routes contain labelled sample reviews, never production fallback data. The current database has no published public occurrences to demonstrate a populated live list; authorization, counts and pagination are verified using rolled-back fixtures rather than committed reviews.

The redundant tinted venue/host card and its host-details sheet were removed at the user’s request. Reviews follow the description directly; venue location remains in the header and map.
