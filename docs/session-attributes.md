# Session attributes and venue amenities

First functional version, 20 October 2026. UI follows the provisional `session-attributes-flow.html` conversation mockup; visual refinement is deferred at the user’s request.

Session inclusions: Balls provided, New balls, Spare rackets available, Coaching, Snacks included, Drinks included. Venue amenities/services: Free parking, Paid parking, Showers, Changing rooms, Lockers, Water dispenser, Accessible facilities, Racket rental, Equipment shop, Café / bar. Empty selections mean unspecified; no negative claims or sample production attributes are inferred.

Basic Info contains an optional inclusion picker and an Edit amenities sheet. Sheet changes are tentative until Apply amenities; closing discards them. Applying updates the form, and draft saving retains selections without changing reusable venue claims. Publishing or updating a session saves venue claims atomically with the session. The sheet explains this boundary. Venue selection loads only the current organizer’s saved claims; changing a manually entered name/address clears claims from the previous venue. The review step includes both groups.

`attribute_definitions` stores stable codes/scope/active status. `organizer_venue_attributes` stores organizer + venue claims because physical venue records are shared. `session_series_attributes` stores template defaults, including draft selections. `session_attributes` stores each occurrence’s actual inclusions. Composite scope foreign keys and primary keys reject wrong-group and duplicate selections; RLS enforces ownership and active organizer access. Past/cancelled occurrence attributes cannot be modified through client grants.

The existing session-save RPC remains SECURITY INVOKER and keeps its existing locking, optimistic versions, input rules and idempotent publish retries. It validates codes even in drafts, normalizes New balls to avoid a duplicate Balls provided chip, copies selections on creation and respects one/future edit scope. One-occurrence changes leave series defaults alone. Venue changes serialize per organizer/venue and compare the original selection before writing; a stale change rolls the entire save back. Requests from older clients without attribute fields preserve current selections.

Venue claims describe current facilities for that organizer’s sessions at the venue; they are not independently verified and are not historical snapshots. This does not add venue ownership, venue verification, rental booking or service pricing. Free and paid parking may coexist. No existing venue or session is backfilled with guessed amenities.

The existing public detail RPC projects the occurrence’s inclusions and its host’s venue claims after the existing visibility check. It exposes no selection baselines, ownership IDs, drafts, or other organizers’ private data. Base attribute tables have no anonymous grants. Public detail replaces the generic metadata chips with What’s included and At the venue; missing groups are hidden. Duration remains in the date summary; participation and weekly recurrence remain readable as plain metadata.

Labels/icons live in the feature’s typed UI catalog; new supported codes require a matching catalog migration and app release. Shared attribute chips provide selection semantics and passive display. The existing query/service/repository boundaries and memory-only public query caches remain in use; saving invalidates public detail and organizer inventory.

Attribute chips use a consistent 1.8-unit icon stroke. Balls provided and New balls use the shared original `PadelBallIcon`; Spare rackets available uses `PadelRacketIcon`, whose smooth loop, head and neck follow the user’s fuller racket reference. These and `PadelRacketBallIcon` are native vectors built with `createLucideIcon` and the existing AppIcon props, sizing and stroke defaults. The combined racket/ball variant is used by the shared RoleTabs secondary tab (Sessions for organizers, My games for players), with the same 2-unit stroke as the other navigation icons. It is not used by the attribute catalog. This icon extension adds no raster assets or theme tokens.

Rollback-only database checks: `supabase/tests/session-attributes.sql`. Native no-write QA: `/sessions-preview/attributes`, using the actual SessionForm, and `/sessions-preview/public-session`, using PublicSessionView. The preview can save/resume draft state locally and display the exact selected chips without touching an account. `state=error` simulates one failed save followed by successful retry.
