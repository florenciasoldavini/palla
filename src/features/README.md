# Features

Product code lives here and is grouped by capability, not by technical layer.

Each feature may own `components`, `hooks`, `queries`, `mutations`, `schemas`, and `types`. Only move code into shared top-level folders after it has a genuine cross-feature use case.

Planned MVP boundaries include `auth`, `session-discovery`, `registration`, `waitlist`, `organizer-dashboard`, and `notification-preferences`. They are intentionally not scaffolded until implementation starts.
